# Firebase Hosting + Terraform Design

**Date:** 2026-05-23
**Status:** Approved

## Problem

`firebase-config.js` is committed with placeholder values that must be manually replaced after Firebase project setup. This is fragile and non-standard.

## Goal

Provision the entire Firebase backend with Terraform and switch to Firebase Hosting so that `/__/firebase/init.js` auto-injects the project config — no config file in the repo at all.

---

## Architecture

**Terraform** (`terraform/`, local state) provisions everything in one `apply`:
- GCP project via `project-factory` module
- Firebase, Firestore, Hosting, Identity Platform, WIF + service account for GitHub Actions

**App** loses `firebase-config.js` entirely. Firebase Hosting serves `/__/firebase/init.js` automatically once the web app is registered.

**Deploy**:
- Push to `master` → GitHub Actions → OIDC auth → `firebase deploy`
- Or manually: `firebase login` + `firebase deploy`

**One manual step** after `terraform apply`: enable Google Sign-In in Firebase Console (Firebase auto-creates the OAuth client; automating this would require storing OAuth credentials in Terraform, which introduces secrets).

---

## File Structure

```
terraform/
  main.tf          — project-factory module + all Firebase resources
  variables.tf     — billing_account_id, project_id, region
  outputs.tf       — project_id, hosting_default_url, wif_provider, wif_service_account
  .gitignore       — .terraform/, *.tfstate, *.tfstate.backup, .terraform.lock.hcl
terraform.rules    — Firestore security rules (read by main.tf and firebase.json)
firebase.json      — hosting: public ".", ignores for terraform/, *.md, *.test.js
.firebaserc        — generated by Terraform local_file (gitignored); GitHub Actions uses --project flag
.github/
  workflows/
    deploy.yml     — on push to master: OIDC auth → firebase deploy --only hosting,firestore:rules
README.md          — updated with setup steps
index.html         — replace firebase-config.js script tag with /__/firebase/init.js
.gitignore         — add firebase-config.js, .firebaserc, terraform/.terraform/, terraform/*.tfstate*
```

`firebase-config.js` is deleted.

**Terraform providers required:** both `hashicorp/google` and `hashicorp/google-beta`. Firebase-specific resources (`google_firebase_project`, `google_firebase_web_app`, `google_firebase_hosting_site`, `google_identity_platform_config`) use the beta provider. Firestore and IAM resources use the stable provider.

## Terraform Resources

All in `terraform/main.tf`, provisioned in dependency order:

| Resource | Purpose |
|----------|---------|
| `module "project"` (project-factory) | Create GCP project, link billing, enable APIs |
| `google_firebase_project` | Enable Firebase on the project |
| `google_firebase_web_app` | Register web app — feeds `/__/firebase/init.js` |
| `google_firestore_database` | Native mode, `nam5` region (free tier) |
| `google_firebaserules_ruleset` | Security rules from `terraform.rules` file |
| `google_firebaserules_release` | Publish rules to Firestore |
| `google_firebase_hosting_site` | Create hosting site |
| `google_identity_platform_config` | Enable Identity Platform (Auth shell) |
| `google_service_account` | Service account for GitHub Actions |
| `google_iam_workload_identity_pool` | WIF pool for OIDC |
| `google_iam_workload_identity_pool_provider` | Bound to `cafanasyev/fitness-calendar` |
| `google_project_iam_member` (×2) | SA gets Firebase Hosting Admin + Firebase Rules Admin |
| `google_service_account_iam_member` | Allow WIF to impersonate the SA |

**APIs enabled** (via project-factory `activate_apis`):
`firebase.googleapis.com`, `firestore.googleapis.com`, `identitytoolkit.googleapis.com`,
`firebasehosting.googleapis.com`, `firebaserules.googleapis.com`,
`iam.googleapis.com`, `cloudresourcemanager.googleapis.com`,
`iamcredentials.googleapis.com`

**Variables:**

| Variable | Description |
|----------|-------------|
| `billing_account_id` | GCP billing account (format: `XXXXXX-XXXXXX-XXXXXX`) |
| `project_id` | Globally unique GCP project ID (e.g. `fitness-cal-abc123`) |
| `region` | Default region, defaults to `us-central` |

**Outputs:**

| Output | Used for |
|--------|---------|
| `project_id` | Set in `.firebaserc` |
| `hosting_default_url` | Verify deploy |
| `wif_provider` | GitHub secret `WIF_PROVIDER` |
| `wif_service_account` | GitHub secret `WIF_SERVICE_ACCOUNT` |

## GitHub Actions Workflow

`.github/workflows/deploy.yml` — triggers on push to `master`:

1. Checkout repo
2. `google-github-actions/auth` — exchange OIDC token for GCP credentials using `WIF_PROVIDER` + `WIF_SERVICE_ACCOUNT` secrets
3. `npm install -g firebase-tools`
4. `firebase deploy --only hosting,firestore:rules --project $PROJECT_ID`

`PROJECT_ID` is stored as a GitHub Actions variable (not secret — it's not sensitive).

## App Changes

### index.html

Replace:
```html
<script src="firebase-config.js"></script>
```
With:
```html
<script src="/__/firebase/init.js"></script>
```

The `/__/firebase/init.js` URL is a reserved Firebase Hosting path that auto-serves the project's Firebase config. It only works when served from Firebase Hosting (or the local emulator `firebase serve`).

### firebase-config.js

Deleted entirely.

### .gitignore

Add:
```
firebase-config.js
.firebaserc
terraform/.terraform/
terraform/*.tfstate
terraform/*.tfstate.backup
terraform/.terraform.lock.hcl
```

## Firestore Security Rules

Stored in `terraform.rules` at project root (shared between Terraform and `firebase.json`):

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{uid} {
      allow read, write: if request.auth.uid == uid;
    }
  }
}
```

## README Setup Steps

```markdown
## Setup

### 1. Prerequisites

```sh
npm install -g firebase-tools
# Install Terraform: https://developer.hashicorp.com/terraform/install
gcloud auth login
gcloud auth application-default login
```

### 2. Provision infrastructure

```sh
cd terraform
terraform init
terraform apply
# Prompts for: billing_account_id, project_id
```

### 3. Enable Google Sign-In (one manual step)

Firebase Console → your project → **Authentication → Sign-in method → Google → Enable**

This cannot be automated — Firebase auto-creates the OAuth client on first enable.

### 4. Add GitHub Actions secrets

From `terraform output`, copy and add to **GitHub → Settings → Secrets and variables → Actions**:

- `WIF_PROVIDER` — Workload Identity provider resource name
- `WIF_SERVICE_ACCOUNT` — service account email

Also add a repository **variable** (not secret): `FIREBASE_PROJECT_ID`

### 5. Deploy manually (optional)

```sh
firebase login   # first time only
firebase deploy
```

Push to `master` triggers automatic deploy via GitHub Actions.
```

## Local Development

`/__/firebase/init.js` only resolves on Firebase Hosting. For local dev, use the Firebase emulator:

```sh
firebase serve
# or
firebase emulators:start --only hosting
```

This serves the app at `http://localhost:5000` with the real Firebase project config injected.
